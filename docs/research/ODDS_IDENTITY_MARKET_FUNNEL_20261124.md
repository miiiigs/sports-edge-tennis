JSON normalized input (operator must export separately with read-only role/transaction, rights-cleared data, no secrets; this PR does not implement the DB export adapter):
- audit_at: timezone-aware UTC cutoff for evidence collection. fixtures: one per already eligible canonical main-draw ATP/Challenger singles fixture, match_id, source_ids (exact source namespace -> string), players (ordered canonical IDs), verified_tournament_ids (independently matched edition allowlist of provider tournament IDs), start_at (frozen schedule), cutoff (original issuance or scheduled T-30 min for independent future experiment, never after audit_at).
- events: event_id (OddsPapi fixtureId), external_ids (only independently validated SPORTRADAR from betradarId, and PINNACLE only if same identifier namespace proven, not assumed PINNAPI), canonical_players (ordered provider slots independently verified via player ID crosswalk), tournament_id, observed_at (actual observation of identity, not current export time), start_at. Supply one immutable event snapshot per ID for the audit slice; multiple inconsistent snapshots fail closed. Do not infer ID equivalence from raw numbers or names. API_TENNIS direct linkage not documented; no assumed direct mapping.
- quotes: event_id, bookmaker (licensed slug), source, market MATCH_WINNER, player_id (verified canonical identity), observed_at, as_of, ingested_at, status OPEN/SUSPENDED/etc, price decimal. All three timestamps required and ordered. Provide original normalized snapshots, including suspension updates; no backdated ingestion. Separate audit slice per original cutoff to avoid the 24h current identity age rule excluding historical fixtures. No source or bookmaker mixing. Exporter must preserve coverage denominator, source capture IDs/hashes, verified participant side mapping and original publication times. Do not publish raw licensed rows to GitHub. No archived odds fed into this live-available tool.

Output: unique fixtures and per-fixture identity state, per-book market state for verified identities, count of fixtures with any qualified book, input SHA256. Missing identity distinct from no stored market; latter is not proof a provider lacks a market. Late, stale, suspension, invalid side/price, incomplete, ambiguous and unsynchronized state separated. Exact duplicated rows deduplicate; conflicting fixtures fail closed. Latest side state is used, including suspension; no fallback to earlier open quotes. Strict timestamp and source checks; conservative rejection of ambiguous states. This is a diagnostic of supplied evidence only, not actual recovery, a DB census, or production deployment. Unit tests are synthetic, not provider observations.
